    Declare five interfaces in dependency order (sub-types first):

    1. `ReferenceInput` — mirrors `Reference` from `src/domain/Question.ts` but with all fields optional; use `fonte?: { codigo: number; descricao: string; anoFonte?: number } | null` (inline object, matches `ReferenceSource` shape without importing the domain type).

    2. `AssessmentLayoutInput` — explicitly lists every field the renderer reads from `AssessmentLayout`; no `[key: string]: any` index signature; no `any`-typed fields. Include: `codigo`, `nome`, `cabecalho`, `rodape`, `folhaRosto`, `paginacao`, `tipoFolha`, `margem`, `cabecalhoQuestao`, `cabecalhoPrimeiraQuestao`, `orientacaoFolha`, `rodapeRosto`, `rascunho`, `colunas`, `marcaDagua`, `fonte`, `fonteTamanho`, `origemQuestao`, `ordemQuestaoPersonalizada`, `tipoAlternativa`, `quebraQuestao`. All fields optional. Types: number fields as `number`, string fields as `string`, booleans as `boolean`, `rodapeRosto` as `string | null`.

    3. `AttachmentInput` — two fields only: `ordem?: number`, `anexo?: { texto?: string }`. No index signature on either the outer interface or the `anexo` inline object.

    4. `QuestionInput` — plain data shape (not the domain entity constructor). Fields: `id?: number | string`, `order: number` (required), `customOrder?: number | null`, `value: number` (required), `type: string` (required), `reference?: ReferenceInput | null`, `visualizaQuestaoRaw?: string | null`, `orderAlternative?: number`, `title?: string | null`, `linhasBranco?: number`, `quebraPagina?: boolean`, `visualizaResposta?: string`, `tipoLinha?: { codigo: number; nome: string } | null`, `numeroLinhas?: number`. Use the `{ codigo: number; nome: string }` inline object type for `tipoLinha` (per D-03 from STATE.md — the fixture confirms object shape, not string).

    5. `AssessmentInput` — top-level contract: `id?: number | string`, `title?: string`, `questions?: QuestionInput[]`, `attachments?: AttachmentInput[]`, `layout?: AssessmentLayoutInput`.

    All interfaces use `export interface`. No class definitions, no runtime code, no imports from `../domain/` (per RESEARCH.md Pitfall 3 — `AssessmentInput` is independent of `AssessmentConstructor`).

    After writing the file, run `npx tsc --noEmit` from the project root and confirm it exits 0. If errors surface in unrelated files, do not fix them — report them. If errors are in the new file itself, fix them before proceeding.
